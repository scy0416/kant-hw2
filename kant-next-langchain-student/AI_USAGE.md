# AI 사용 기록

허용 범위는 개념 질문과 자신이 작성한 코드의 디버깅입니다. 과제 함수의 정답이나 전체 구현을 대신 생성하게 해서는 안 됩니다. 먼저 현재 단계 검사를 실행하세요.

사용하지 않았다면 아래에 사용하지 않았다고 적습니다. 사용했다면 질문마다 기록합니다. API 키, 개인 이메일, 실제 회사 데이터는 입력하지 않습니다.

| 구분 | 질문 요약 | 공유한 자기 코드와 오류 범위 | 이해한 내용 | 직접 수정하고 검증한 결과 |

| 디버깅 확인 | "필수 2가 문제없이 통과했는지 확인해줘" | 필수 2의 `build_prompt_and_parser`, `validate_sources`, `build_primary_chain`, `build_answer_chain`. | 디버깅 확인 | "진행해봤는데, 문제가 몇 개 확인되는데, 왜그런걸까?" (필수 5) | 필수 5의 `stream_answer`, `TraceHandler`. AI가 `check stream`을 실행함(19개 중 3개 실패) | (1) `stream_answer`의 출처 검사가 예외를 내지 않고 `safe_answer()`로 대체해서 reset 없이 final로 가고, 인자 없는 `safe_answer()`는 기본값이 `no_documents`라 문구도 맞지 않으며, 중복과 출처 없는 해결 답변은 검사하지 않는다는 점을 이해함. 필수 2의 `validate_sources`가 세 조건을 모두 예외로 거부하고 그 예외가 `support.RECOVERABLE`에 속해 기존 reset/fallback 경로로 간다는 점을 안내받음. 도구와 모델 이름: Claude Code (Claude Sonnet 5.5, claude-sonnet-5-5). 사용 범위는 필수 1~5의 분석, 개념 설명, 작성한 코드의 검사 실행과 오류 지적이며, 선택 심화는 진행하지 않았습니다. 필수 5의 코드는 AI가 쓰지 않았고 제가 직접 작성했습니다. 이 표는 AI가 대화 내용을 바탕으로 정리했고, 저는 사실과 맞는지 확인해야 합니다.

AI의 설명이 틀렸거나 그대로 적용하지 않은 부분: 현재까지 AI의 설명이 틀린 것으로 확인한 부분은 없습니다. 그대로 적용하지 않은 부분은 두 가지입니다. (1) 필수 1의 작성 이유에 "서로의 결과를 필요로 하지 않음"과 "검색 함수 교체"를 더하라는 보강 제안은 아직 반영하지 않았습니다. (2) 필수 3의 작성 이유는 지적을 받은 뒤 `fallback`과 중단된 스트림까지 포함하도록 직접 고쳤지만, "문서와 이력의 역할 차이"를 설명하는 부분은 보강 여지가 남아 있습니다. 또한 필수 5에서는 AI가 오류 원인과 함께 사용할 기존 함수(`validate_sources`)를 지목했고 저는 그 방향으로 직접 고쳤습니다. 제출 전에 이 도움의 정도를 사실대로 판단해 주세요.
